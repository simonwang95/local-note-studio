## P0：完成状态与数据保护

### T-006 统一完成状态与补跑校验

状态：已完成（2026-09-29，`codex/p0-p1-backlog`）。优先级：P0。前置：无。

问题依据：隔离样例复现了本地目录任务校对失败后仍返回退出码 `0`，且开启“保留原始字幕”时，带 AI 占位符的文件通过 Worker 最终校验。另一个样例中，已有校对正文损坏、摘要待补齐时，程序使用原始转写继续生成摘要，并保留损坏正文。单文件与目录入口的失败判定目前不一致。

实施范围：

- 在 Worker/公共校验层统一每类视频任务的必需栏目、占位符、来源与质量检查；字幕保留选项只决定原文是否显示，不决定任务是否合格。
- 明确 `generate_summary` 的完成、部分完成、无变化和失败结果，避免以“文件写入过”或布尔返回值代替完成状态。
- 补跑先验证已有校对正文；不合格时重做校对，有合格正文后再生成衍生栏目。缺少可恢复原文时明确提示重转写，不降级为假成功。
- 单文件、目录、收藏夹和 UP 批量路径使用同一判定，向 GUI/CLI/MCP 输出一致的状态、计数、可恢复步骤；只将合格结果标记为已处理。

验收标准：

- 本地目录校对失败、保留原文开启/关闭两种组合均不能显示完全成功；失败文件保留可恢复材料。
- 缺少必需栏目、残留占位符、已有坏正文三类 fixture 被拦截；兼容明确允许仅转写的任务合同。
- 合格旧结果跳过时不触发 ASR/LLM；只有部分栏目缺失时复用已验证的正文。
- 混合成功/失败批次计数、退出状态、历史记录和重试范围一致；失败条目不进入完成索引。

代码入口：[批量转写与补跑](../worker/scripts/bilibili/batch_transcribe.py)、[视频编排](../worker/scripts/run_bilibili_transcript.py)、[Worker 最终校验](../worker/local_note_studio_worker.py)。扩展现有 `tests/test_worker.py`、`tests/test_transcript_quality.py`、`tests/test_automation.py` 的失败路径用例。

### T-007 视频输出暂存、覆盖保护与索引一致性

状态：已完成（2026-09-29，`codex/p0-p1-backlog`）。优先级：P0。前置：T-006。

问题依据：当前视频流程先向正式路径写入转写草稿，再进行 AI 整理；启用覆盖时，后续失败可能留下不完整的新文件。笔记及部分 Manifest 使用直接写入，尚未形成统一的可恢复提交过程。此项来自代码审查，未对用户正式笔记执行破坏性故障实验。

实施范围：

- 视频原文、校对、摘要和关键帧先在任务暂存区完成；使用 T-006 标准验证后才发布正式结果。
- 覆盖前保存旧笔记及对应资产的恢复信息；正式 Markdown 使用同一文件系统上的原子替换。
- 资产、正文和索引跨文件提交使用可恢复的提交记录，记录完成顺序；只更新当前来源，保留其他任务记录。
- 失败和取消保留可恢复暂存结果；成功后的清理不得删除用户新增内容或其他笔记引用的资产。

验收标准：

- 在 ASR、LLM、关键帧和最终校验阶段分别注入失败，原有完整笔记及资产的校验值保持不变。
- 首次生成失败时，正式目录不出现伪装成完成结果的草稿；历史中可定位恢复入口。
- 正文替换和索引写入之间发生中断后，重启能够回滚或补交，明确当前有效版本，不静默丢失旧成果。
- 重复提交幂等；无覆盖权限时不替换既有文件；用户在运行期间修改目标文件时检测冲突并保留两份结果。

代码入口：[转写输出](../worker/scripts/bilibili/bilibili_transcript.sh)、[视频后处理与 Manifest](../worker/scripts/run_bilibili_transcript.py)、[现有转换暂存流程](../worker/local_note_studio_worker.py)。优先复用已存在的草稿恢复机制，保留 Worker 的跨进程锁。

## P1：恢复、质量与日常操作

### T-114 校对分段检查点与有限细分重试

状态：已完成（2026-09-29，`codex/p0-p1-backlog`）。优先级：P1。前置：T-006、T-007。

问题依据：成功校对段目前仅保存在内存；后段失败或取消后，前段成果不能按段恢复。质量失败只会对同样大小的原段重试一次。

实施范围：

- 每段通过检查后原子保存结果及来源范围；检查点包含原文哈希、模型标识、提示词/规则版本、有效参数和分段边界。
- 恢复时验证兼容性和结果质量，跳过已完成段，仅重做失效或失败段；全部通过后才合并生成摘要。
- 保留默认 8000 字符与前后各最多 240 字符只读原文。对截断或持续质量失败的段有限细分，明确最小段长、最大深度和总调用预算；认证/配置错误不触发细分。
- 状态展示本次调用与复用段数，并区分网络重试、质量重试和细分。隐身模式不持久保存正文检查点，遵循现有隐身合同。

验收标准：

- 三段任务第 3 段失败后再次运行，前两段不调用模型；取消/重启后具有相同行为。
- 改变原文、模型、提示词或影响输出的参数时，相应检查点失效，不能错误复用。
- 细分后的来源范围完整且不重叠，合并后通过覆盖检查；达到预算后明确失败，不无限重试。
- 超长输出、局部漏段和网络错误分别走预期路径；摘要只接收已通过校验的完整正文。

代码入口：[独立分段校对](../worker/scripts/bilibili/batch_transcribe.py)、[缓存与质量检查](../worker/scripts/transcript_quality.py)、[任务恢复](../worker/local_note_studio_worker.py)。

### T-115 按阶段统一参数与展示有效配置

状态：已完成（2026-09-29，`codex/p0-p1-backlog`）。优先级：P1。前置：T-006；细分参数已接入 T-114。

问题依据：界面的通用分块大小未控制独立校对；思考、超时和重试设置在不同阶段的映射范围不同，用户难以判断最终生效值。

实施范围：

- 为校对与摘要/通用整理分别定义段长、思考、超时、重试和冷却的含义与映射；无关参数按任务隐藏或禁用。
- 统一默认值、环境变量和本次覆盖的优先级；启动预览展示各阶段生效值及来源，不显示凭据。
- 兼容旧设置，明确空值与 `0` 的区别；校对默认 8000 字符，单独说明上下文字符数与模型输出 token 预算。
- 记录配置快照，进度显示当前阶段、段数、复用数和等待原因；该合同供 T-201 与 T-205 复用。

验收标准：

- GUI/CLI/MCP 相同有效配置产生一致 Worker 参数；测试断言实际 LLM 请求中的思考、超时、重试和输出预算。
- 用户修改校对段长后，预览值、实际分段和日志一致；越界值明确提示，不静默误导。
- 留空、显式零、旧设置迁移均有覆盖；历史可复核当时使用的值，修改当前设置不改变运行中任务。

代码入口：[任务表单](../src/main.ts)、[历史设置](../src/p1.ts)、[Worker 参数映射](../worker/local_note_studio_worker.py)、[模型请求](../worker/scripts/bilibili/batch_transcribe.py)。

### T-116 关键内容变化提示与原文复核

状态：已完成（2026-09-29，`codex/p0-p1-backlog`）。优先级：P1。前置：T-006、T-114。

问题依据：隔离样例将“不建议加仓”改为“建议加仓”、将“50万片”改为“500万片”，当前机械检查仍通过。既有长度/覆盖检查不等于语义或事实校验；转写原文本身也可能出错。

实施范围：

- 对齐原文与校对段，提示数字、单位、否定词、方向词、专有名词和代码的关键变化，展示对应上下文及来源位置。
- 区分允许的格式归一化与待人工复核的含义变化；疑点不自动猜改，不默认增加一次全文模型重写。
- 视频流程复用确定性的证券代码清理规则；术语表区分“原文明确出现”和“模型新增/推断”，避免将猜测包装为已核验主体。
- 保存复核状态与修改来源；原文有时间戳时支持回看音频/视频，没有时定位文字片段。时间轴能力与 T-117 共享。

验收标准：

- 否定丢失、买卖方向变化、数量级/单位变化和公司名称替换样例进入复核列表。
- 正常标点修复、数字书写归一化和有依据的同音字纠正不被一概当作失败；建立少量固定样例评估漏报与误报。
- 原文没有的证券代码不被静默写成原话；无法确认的简称保留待核验状态。
- 用户可以查看对照并保留、修正或标记疑点；不会将人工复核完成宣称为外部事实核验完成。

代码入口：[质量检查](../worker/scripts/transcript_quality.py)、[证券规则](../worker/scripts/stock_reference.py)、[视频校对](../worker/scripts/bilibili/batch_transcribe.py)。

### T-117 校对正文与关键帧的时间戳对齐

状态：已完成（2026-09-29，`codex/p0-p1-backlog`）。优先级：P1。前置：T-114 的分段来源信息；复核位置与 T-116 共用。

问题依据：关键帧时间目前主要按笔记段落位置占比估算，再吸附到场景时间；新增摘要或术语章节可能改变估算位置。已有 ASR 时间戳尚未贯通到校对段落和图片说明。

实施范围：

- 建立校对段落到原始转写片段及时间范围的映射，关键帧根据对应时间选取，继续保留黑屏/转场/重复画面过滤。
- 图片附近文字来自对应片段；摘要的章节顺序不再参与估算讲话时间。
- 保留字幕时间戳；对于无时间戳的纯文本来源提供明确标注的估算降级，并记录匹配可信程度。

验收标准：

- 增加、删除或重排摘要章节不改变同一讲话片段对应的时间点。
- 固定视频样例中，关键帧落在对应转写范围内；图片摘录能追溯至该片段。
- 无时间戳、时间不连续、对齐失败时明确降级，不输出伪精确的对应关系。
- 重新生成不删除其他笔记资产；Manifest 记录时间范围、来源和对齐方式。

代码入口：[关键帧算法](../worker/scripts/video_keyframes.py)、[ASR 分段](../worker/scripts/bilibili/whisper_transcribe.py)、[视频 Manifest](../worker/scripts/run_bilibili_transcript.py)。

### T-118 缓存管理与任务诊断

状态：已完成（2026-10-04，0.1.29 内部包验收通过，已合并本地 `main`）。优先级：P2。前置：T-114；队列引用保护衔接 T-205。

问题依据：原文、ASR 结果与时间戳已持久保存，但缺少按任务查找、占用统计、保留期限及清理入口；多次 ASR 会生成多份带时间标识的诊断记录。

实施范围：

- 按任务/来源区分原文证据、ASR 诊断、成功检查点、失败恢复材料和可清理缓存，展示大小、时间、状态及引用关系。
- 提供清理预览、手动清理与可配置保留策略；自动清理默认行为需明确，受运行、排队和待恢复任务引用的材料必须保留。
- 汇总阶段耗时、模型调用次数、tokens、重试原因、缓存命中及生效配置；缺失指标标为未知。
- 诊断导出默认脱敏，原文和完整路径需用户明确选择；正常升级不清空证据，隐身模式不新增持久正文缓存。

验收标准：

- 清理仅作用于选中类别，不删除源视频、正式笔记、仍被引用的资产或有效恢复材料。
- 运行/排队任务与清理同时发生时引用保护有效；预览大小和清理结果可复核。
- 有证据的失败任务可定位到原文与重试段；导出不含 API Key、Cookie 内容或未选择的原文。

代码入口：[缓存维护](../worker/cache_maintenance.py)、[诊断事件](../worker/scripts/task_diagnostics.py)、[诊断缓存](../worker/scripts/transcript_quality.py)、[ASR 记录](../worker/scripts/bilibili/whisper_transcribe.py)、[状态审计](../worker/automation_core.py)、[界面](../src/main.ts)。

完成边界与验收（2026-10-04）：

- 校验页按任务/来源、类别查看占用与保护关系，历史失败项可定位诊断和恢复材料；新 GUI 任务历史与 Worker 共用运行 ID。
- 清理只接受固定类别/期限预览的 `preview_id`，执行前重新检查文件指纹与引用。队列同步、保留策略和清理复用全局锁；预览后新增引用、目录/集合队列、旧运行引用、脱敏文件名、符号链接、硬链接、损坏引用状态均有回归。源视频、正式笔记、输出资产和有效恢复材料受到保护。
- 自动清理默认关闭，配置后仅在非隐身处理任务开始前执行；旧缓存缺少可靠来源或状态时保守保留。诊断汇总/事件/锁文件单独统计为“诊断审计保留”，暂不参与清理，以免部分删除改变可复核统计。
- 记录实际 ASR/LLM 请求、服务端用量、阶段耗时、重试、缓存复用与有效配置；缺失值保留为未知。默认导出排除原文和完整路径，显式选择正文时仍屏蔽 Cookie header/Netscape Cookie 和凭据；隐身不新增持久正文或诊断事件。
- `npm run release:check`：前端构建及两组回归、281 项 Python、11 项 Rust、发布配置通过；Shell 语法与空白检查通过。0.1.29 arm64 app 和只读挂载 DMG 的 37 个资源、内嵌前端、签名及 18 次 Worker stdin 请求均通过；原生测试副本验证了库存、保护、750 字节预览、未知指标和实际下载的脱敏 JSON。自动化证据见上述缓存/诊断测试及 `scripts/verify_packaged_p2.py`；完整记录见[0.1.29 验收](acceptance-0.1.29.md)。未调用真实模型或替换已安装应用。

## 开发与验收约定

- 当前已列“待开发”的 P0/P1/P2 项目均已完成；后续先明确候选评估或独立发布验收范围。每个独立任务使用一个开发线程，先阅读本文件对应条目、`agent.md`、进展和 Git 状态。
- 各任务先补能复现问题的必要用例，再实现；修复已有问题时不能只依赖旧测试全部通过。
- 代码、README、使用/配置说明及进展同次更新；状态只有达到本条验收标准后才改为完成。跨任务未完成部分继续留在本清单。
- 原有全局锁、Agent 权限约束、隐身行为和用户文件保护继续有效；业务仍由 Worker 统一执行。
- 修改模型流程后区分 mock/确定性测试与真实模型验收，记录版本、有效参数、耗时和质量边界；配置改动不能宣称已经真实生成验证。
- 打包前执行适当回归和发布检查，核验 DMG 内应用、版本与 Applications 入口；文档调整本身不需要重打包或修改应用版本。

可用于后续独立验收的请求：

> 验收 T-118 桌面缓存管理入口：在独立测试数据与运行环境中验证队列引用、清理预览、恢复定位和脱敏导出，记录 GUI 操作与结果；不要操作正式用户笔记或凭据。公开发布仍按 T-108/T-109 单列门槛验收。
